APPLY THIS CHANGE TO app/Models/User.php
==========================================

Replace the existing getProfilePhotoUrl() method with the version below.

The bug: onboarding (ProviderOnboardingController::storeProfileBuilder) and
the doctor profile edit page both save the uploaded photo onto
`doctor_profiles.profile_photo_path` (it's in DoctorProfile::$fillable),
but this method was reading `$this->profile_photo_path` off the USER row
instead — a column that either doesn't exist there or is never written to.
That's why the photo never showed even though the upload "succeeded".

--- BEFORE ---

    public function getProfilePhotoUrl(): string
    {
        return $this->profile_photo_path
            ? asset('storage/'.$this->profile_photo_path)
            : 'https://ui-avatars.com/api/?name='.urlencode($this->name).'&color=7F9CF5&background=EBF4FF';
    }

--- AFTER ---

    public function getProfilePhotoUrl(): string
    {
        // Doctors: photo lives on doctor_profiles.profile_photo_path.
        // Patients: photo lives on patient_profiles.profile_photo_path
        // if that column exists there too — remove this line if it doesn't.
        $path = $this->profile_photo_path
            ?? $this->doctorProfile?->profile_photo_path
            ?? $this->patientProfile?->profile_photo_path
            ?? null;

        return $path
            ? asset('storage/'.$path)
            : 'https://ui-avatars.com/api/?name='.urlencode($this->name).'&color=7F9CF5&background=EBF4FF';
    }

Note: this checks $this->profile_photo_path first (in case it IS a real
column on `users` for some other part of the app), then falls back to the
doctor profile, so nothing else that might rely on the old behavior breaks.

Also make sure `php artisan storage:link` has been run at least once —
without it, `asset('storage/...')` URLs 404 even when the file uploaded
and saved correctly.
